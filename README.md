# Aletheia-style Generate → Verify → Revise scaffold for CLI agents

Generated by Claude conversation
https://claude.ai/share/cece5d65-1129-4dbd-9099-f59a827abd46

Minimal, **prompt-only** reimplementation of the core loop described in
*"Towards Autonomous Mathematics Research"* (arXiv 2602.10177 v2, Google DeepMind).

## Key insight from the paper

> Decoupling a reasoning model's final output from its intermediate thinking
> tokens, and adding well-chosen prompt scaffolding, enables the model to
> recognize flaws it initially overlooked during generation.

The core value comes from **three role prompts** and one **entry orchestrator
prompt**.

```
┌──────────┐      ┌──────────┐      ┌──────────┐
│ GENERATOR│─────▶│ VERIFIER │─────▶│ REVISER  │──┐
└──────────┘      └──────────┘      └──────────┘  │
      ▲                                            │
      └────────────── loop (≤ N) ──────────────────┘
```

## Files

| File | Purpose |
|---|---|
| `orchestrator.md` | Entry prompt that runs the full autonomous GVR loop |
| `aletheia.sh` | Launcher helper for an interactive agent session |
| `prompts/generator.md` | Subagent: produce a candidate solution |
| `prompts/verifier.md` | Subagent: adversarially audit the solution |
| `prompts/reviser.md` | Subagent: patch only what the verifier flagged |
| `run.sh` | Headless batch driver (pipe-based loop) |

## Quick start — interactive session

```bash
chmod +x aletheia.sh

# Option A: launch, then paste your problem
./aletheia.sh

# Option B: pre-load a problem file
echo "Prove: every continuous bijection from a compact space to a Hausdorff space is a homeomorphism." > problem.md
./aletheia.sh problem.md

# Option C: use a different client command
./aletheia.sh problem.md claude

# Optional: keep client UI/system behavior and append Aletheia prompt
ALETHEIA_PROMPT_MODE=append ./aletheia.sh problem.md codex
```

The orchestrator runs autonomously: no per-step "proceed?" checkpoint.

## Alternative — headless batch mode

```bash
chmod +x run.sh
./run.sh problem.md            # defaults to codex (internally: codex exec -)
./run.sh problem.md 3 claude   # Claude Code (internally: claude -p)
./run.sh problem.md 5 gemini   # other clients: passed through as provided
```

## Design decisions drawn from the paper

1. **Separate verifier prompt** — the paper's §2.2 shows this is the single
   biggest lever; the verifier never sees the generator's chain-of-thought,
   only its final output.
2. **Balanced prompting** — the verifier is told to look for both correctness
   *and* incorrectness ("prove or disprove each step") to prevent confirmation
   bias (noted in v2's companion blog).
3. **Admit failure** — the verifier can output `VERDICT: FAIL` to halt early
   rather than endlessly patching garbage.
4. **Tool-use stubs** — the generator prompt encourages web search and Python
   when available, mirroring Aletheia's tool integration that reduced citation
   hallucinations (§2.3).
5. **Max rounds cap** — the paper uses a "preset hyperparameter limit";
   3–5 rounds is a reasonable default.
6. **Autonomous progression** — after each subagent result, the orchestrator
   commits to the next protocol step without waiting for human confirmation.

## Prompt substitution modes

Some clients expose two ways to inject your entry prompt:

1. **Full replacement**: replace the client's built-in system instructions.
2. **UI-aware append**: keep the client's built-in UI/system behavior and add
   your instructions on top.

### OpenAI Codex CLI

```bash
# Full replacement (uses file path)
codex -c model_instructions_file="$PWD/orchestrator.md"

# UI-aware append (adds instructions to defaults)
codex -c developer_instructions="$(cat orchestrator.md)"
```

### Claude Code

```bash
# Full replacement
claude --system-prompt "$(cat orchestrator.md)"

# UI-aware append
claude --append-system-prompt "$(cat orchestrator.md)"
```
